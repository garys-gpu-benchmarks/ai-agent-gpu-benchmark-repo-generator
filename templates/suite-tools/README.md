# __SUITE_TOOLS_REPO__

Operator tools for the GPU benchmark suite under
[`__CI_OWNER__`](https://github.com/__CI_OWNER__). Generated by
`scripts/emit_shared_workflows.py` in the benchmark repository generator from
`templates/suite-tools/`; change them there.

| Script | Runs on | What it does |
|---|---|---|
| [`scripts/run_benchmark_suite.sh`](scripts/run_benchmark_suite.sh) | the GPU host | Runs the workloads already installed under one folder (default `__SUITE_INSTALL_ROOT__`), one after another, for each requested profile, optionally repeated. One log file for the whole run and a pass/fail summary at the end. It discovers workloads from the folder, so the same script serves all four platforms, and it downloads nothing. |
| [`scripts/get_remote_info.sh`](scripts/get_remote_info.sh) | your laptop (Git Bash on Windows) | Over one SSH connection, copies back the runtime ledger (CSV, plus an Excel copy on Windows), every workload's `results/raw` and `results/parsed`, and the suite logs, into `RUNTIME_LEDGERS/` and `DIRECTORIES/`. |
| [`scripts/show_metrics.sh`](scripts/show_metrics.sh) | your laptop or the GPU host | Prints one workload's runs from the runtime ledger (local file, or over SSH with `--host`) in fixed 7-character metric columns plus an Exit column, with per-profile means. Column headings and the 12-character workload names are generated from the `Metric_Short_Labels` and `Workload_Short_Names` sheets in the generator. |

`run_benchmark_suite.sh` and `show_metrics.sh` are also published at the top of
every bundle repository, next to `run.sh`. Cloning a bundle into
`__SUITE_INSTALL_ROOT__` leaves `show_metrics.sh` there. The generator's remote
copy does the same when it loads a workload onto the VM.

## On the GPU host

```bash
# Put every workload for this machine (AMD + Ubuntu 24.04 shown) in __SUITE_INSTALL_ROOT__
git clone --recurse-submodules https://github.com/__CI_OWNER__/bundle-amd-ubuntu-2404 __SUITE_INSTALL_ROOT__
cd __SUITE_INSTALL_ROOT__
./run.sh list                                     # every workload should show "ready"

./run_benchmark_suite.sh --dry-run                # what would run
./run_benchmark_suite.sh -p smoke                 # quick check of everything
./run_benchmark_suite.sh -w 101,107,121 -p baseline
./run_benchmark_suite.sh -w 101-110 -p smoke,baseline
./run_benchmark_suite.sh -r 20                    # soak test: everything, 20 times

# Later: move to the newest published release
git pull && git submodule update --init --recursive
```

The first run of each workload builds its environment with `setup.sh`, which
may ask for your `sudo` password and, for ROCm, may need one reboot. Logs go to
`__SUITE_INSTALL_ROOT__/benchmark_suite_log/`.

## On your laptop

```bash
./scripts/get_remote_info.sh 203.0.113.10                        # root@host, port 22
./scripts/get_remote_info.sh ubuntu@203.0.113.10 2222            # another user and port
./scripts/get_remote_info.sh -i ~/.ssh/id_ed25519 -o ~/results 203.0.113.10
./scripts/get_remote_info.sh --help

./scripts/show_metrics.sh 332 --host 203.0.113.10                 # workload 332, all profiles
./scripts/show_metrics.sh 332 --baseline --file RUNTIME_LEDGERS/runtime_ledger_301_332_<time>.csv
./scripts/show_metrics.sh --help
```

Without `-i`, it tries your SSH defaults, then each private key in `~/.ssh`.

## Relationship to CI

Each workload repository can also run one benchmark on a self-hosted runner
through its **GPU Smoke Benchmark** workflow (see
[`__CI_SHARED_REPO__`](https://github.com/__CI_OWNER__/__CI_SHARED_REPO__)).
These scripts are the manual, whole-bundle path on the same machines.
